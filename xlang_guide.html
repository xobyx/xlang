The xlang Programming Language

A multi-paradigm, systems-capable scripting and compiled language featuring a Unified Tri-Engine Execution Model: Tree-Walk Interpreter, Stack-Based Bytecode VM, and LLVM Native AOT Compilation.

⚡ Standalone ELF 64-bit Binaries 📦 Single-Inheritance OOP 🌐 Native Berkeley Sockets 🔄 Mark & Sweep GC + Tagged Values

1. Introduction & Philosophy

xlang was designed from first principles in ANSI C to bridge the gap between dynamic ergonomic scripting and deterministic native systems performance. Whether developing microservices, parsing complex protocols, running algorithmic pipelines, or emitting optimized machine code, xlang offers seamless transitions across three execution paradigms without changing a single line of source code.

⚡

Zero-Overhead Semantics

Strict structural layouts and primitive inlining allow direct translation from high-level syntax into LLVM Intermediate Representation without runtime reflection overhead.

🧩

Orthogonal OOP Model

Classes support member variables, overloaded constructors, single inheritance, instance methods, and static methods with single-pass struct alignment.

🌐

Built-in Networking

First-class Berkeley sockets support high-performance TCP server daemons, client requests, UDP datagrams, and timeouts directly in user code.

2. Tri-Engine Execution Architecture

The core innovation of xlang is its Unified Compilation Pipeline. The frontend parses source files into an AST Arena. From that unified AST representation, xlang can execute in three distinct ways:

Figure 2.1: Unified Multi-Tier Compilation & Execution Pipeline 
# Execute directly via AST Interpreter (instant execution, zero build step)
$ ./bin/Release/xlang examples/http_server/server_daemon.xb
# Compile script into compact binary bytecode (.xbc)
$ ./bin/Release/xlang -c examples/http_server/server_daemon.xb -o server.xbc

# Execute bytecode using the high-performance stack VM
$ ./bin/Release/xlang --vm server.xbc
# 1. Inspect generated LLVM IR:
$ ./bin/Release/xlang examples/http_server/server_daemon.xb --emit-llvm

# 2. Build directly into an optimized standalone ELF 64-bit binary via Clang:
$ ./bin/Release/xlang build examples/http_server/server_daemon.xb -o server_daemon_bin

# 3. Run the standalone binary directly (zero xlang dependency):
$ ./server_daemon_bin

6. Object-Oriented Programming & Inheritance

Classes in xlang are first-class constructs with automatic memory allocation, constructors with parameter overloading, single inheritance, instance fields, and instance/static methods.

Figure 6.1: Memory Layout & Field Inheritance Offset Map
oop_demonstration.xb 
class Shape() {
    string name
    Shape(string n) {
        name = n
    }
    void describe() {
        println("Shape: " + name)
    }
}

class Rectangle(Shape) {
    int width
    int height

    Rectangle(int w, int h) {
        name = "Rectangle"
        width = w
        height = h
    }

    int area() {
        return width * height
    }
}

Rectangle rect = new Rectangle(10, 20)
rect.describe()  # Output: Shape: Rectangle (dispatches to base method)
println(rect.area())      # Output: 200

7. Standard Library Modules

xlang includes built-in standard modules for high-performance collections, Berkeley sockets, strings, filesystem operations, and runtime diagnostics.

🗂️

Dynamic Collections: List & Map

Dynamically resizable hash maps and sequential lists capable of storing heterogeneous data with zero manual allocation.

import "list.xb"
import "map.xb"

List names = new List()
names.add("Alice")
names.add("Bob")
println(names.get(0)) # Alice

Map config = new Map()
config.put("host", "127.0.0.1")
config.put_int("port", 8080)
println(config.get("host"))
🌐

Berkeley Sockets & Networking

Full TCP and UDP networking suite with reuse-addr, timeout controls, and non-blocking capability.

import "socket.xb"

int fd = socket_create("tcp")
socket_set_reuseaddr(fd, 1)
socket_bind(fd, "127.0.0.1", 8080)
socket_listen(fd, 32)

int client = socket_accept(fd)
string req = socket_recv(client, 4096)
socket_send(client, "HTTP/1.1 200 OK\r\n\r\nHello")
socket_close(client)

8. LLVM AOT Native Compiler Pipeline

The LLVM backend translates high-level xlang code directly into strongly typed LLVM IR and leverages clang -O2 to compile native, standalone ELF 64-bit binaries.

💡 Pure Native C ABI Linkage
Unlike other interpreted scripting languages, xlang's compiled executables do not bundle a heavy interpreter or virtual machine. They link against a compact 20KB C ABI runtime bridge (xllvm_rt.o) that provides direct POSIX/libc bindings.
xlang Expression Emitted LLVM Instruction Behavior
a + b (strings) call i8* @_str_concat(i8*, i8*) Heap-allocates and concatenates two strings
str == "text" call i32 @str_eq(i8*, i8*) == 1 Exact byte-for-byte content comparison
obj.method() call %ret @Class_method(%struct.C* %this, ...) Direct C ABI dispatch; bitcasts %this on inheritance
s.len() call i32 @_len(i8* %s) Calculates string length via runtime helper

10. Complete Real-World Example: Native HTTP Daemon

The following program demonstrates classes, dynamic collections, sockets, string processing, and health diagnostics compiled into a standalone native binary:

examples/http_server/server_daemon.xb 
import "server.xb"
import "sys.xb"

println("==================================================")
println("       xlang HTTP Web Server is Running!          ")
println("==================================================")
println("Listening on http://127.0.0.1:8080")

HttpServer srv = new HttpServer()
int status = srv.init("127.0.0.1", 8080)

while (srv.is_running != 0) {
    srv.accept_and_serve()
}

srv.close()
